# DueDay 原生 iOS UI/UX 与 Liquid Glass 规范

版本：v0.1 · 2026-08-14  
平台：SwiftUI，首轮覆盖 iOS 17–26  
产品定位：个人固定支付提醒，不是传统记账软件

## 1. 目标与边界

DueDay 的核心问题是“下一笔什么时候到期、我现在需要做什么”。用户打开应用后应在几秒内看到下一笔固定支付、未来七天安排和本月压力，并能快速标记已还。

本规范只定义原生 iOS 的表现层与交互层，不新增登录、后端、信用卡同步、真实支付能力或商业化功能。数据继续按本地优先理解：账单计划描述未来规则，账期保留生成时的历史快照；编辑计划不覆盖已经完成的历史事实。

### Liquid Glass 使用原则

- 只用于导航和操作层：Tab Bar、Navigation Bar、Toolbar、Sheet、主要操作按钮及其浮层承载。
- 内容层保持清晰、温暖、可读：账单名称、金额、日期、状态、表单字段、统计图表不做玻璃化，不使用大面积半透明毛玻璃。
- 不以玻璃替代信息层级。玻璃组件必须仍有明确的边界、选中态、文字标签和可访问名称。
- iOS 26 使用系统 Liquid Glass API；iOS 17–25 使用不透明或轻微半透明的同结构控件，保证信息架构与操作位置不变。

## 2. 信息架构与路由

### 主导航

使用底部 Tab Bar，四个目的地固定为：首页、日历、账单、我的。统计不是新增主业务 Tab：从首页“查看统计”或“我的 > 统计与趋势”进入独立统计页。

| 目的地 | 任务 | 主入口操作 |
| --- | --- | --- |
| 首页 | 确认下一笔、处理近期到期 | 标记已还、新增账单、进入详情 |
| 日历 | 按日期检查到期安排 | 切换月份、选日期、进入详情、新增 |
| 账单 | 管理全部固定支付计划 | 筛选、进入详情、新增 |
| 我的 | 通知、本地数据与应用说明 | 开关提醒、请求权限、备份恢复 |
| 统计 | 查看本月完成、类别分布、未来六个月 | 从首页/我的进入，返回原页面 |

主 Tab 切换保留各页面滚动位置与筛选状态；Tab 切换不播放装饰性转场。新增/编辑使用 sheet 或全屏 sheet；详情使用 NavigationStack push。

## 3. 颜色与材质 tokens

### 内容层色彩

| Token | Light | Dark 建议 | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#F5F3ED` | `#171B18` | 页面背景、清晰内容层 |
| `surface` | `#FCFBF7` | `#222823` | 列表组、输入区、普通面板 |
| `surfaceMuted` | `#EDEBE4` | `#303832` | 已完成/已跳过弱化背景 |
| `ink` | `#17231E` | `#F4F5EF` | 主文字、主要操作 |
| `inkMuted` | `#68736D` | `#AAB4AD` | 辅助说明、次要日期 |
| `accent` | `#1F6A50` | `#6CC49C` | 主操作、待处理、选中 |
| `accentSoft` | `#DCEBE4` | `#234A3B` | 选中背景、提醒提示 |
| `warning` | `#C78B36` | `#E0AE58` | 临近、未知金额提示 |
| `danger` | `#C45F4B` | `#E88470` | 逾期、不可逆确认提示 |
| `divider` | `#E3E1D9` | `#3B443E` | 分隔线、细边框 |

暗色模式的实际颜色需要通过对比度与模拟器校验后微调；不要简单反转色板。红色只表示逾期或危险，不能用于普通强调。

### Liquid Glass tokens

- `glassBar`：导航/工具栏系统玻璃材质，内容滚动时按系统规则增强分离度。
- `glassAction`：主要操作的系统玻璃按钮；文字与图标必须使用 `ink`/`accent` 的高对比前景。
- `glassTint`：仅使用低强度 `accent` tint，避免彩色玻璃覆盖账单内容。
- `glassRadius`：遵循系统容器形状；自定义浮动操作最小 16pt 圆角，sheet 顶部保持系统 drag indicator。
- 不为内容卡片定义 `glassCard` token，防止玻璃扩散到内容层。

## 4. 字体、间距与布局

使用 iOS 系统字体（SwiftUI `.system`），不引入展示字体。金额使用 `.monospacedDigit()`，日期与金额形成明确层级；不要把未知金额显示为 ¥0。

| 语义 | 默认样式 | 备注 |
| --- | --- | --- |
| 页面标题 | Large Title / 30pt、Bold | 支持 Dynamic Type，不锁死高度 |
| 区块标题 | Title 3 / 20pt、Semibold | 如“本月进度”“账期记录” |
| 主金额 | 36pt、Bold、monospaced digit | 页面宽度不足时允许缩小，不截断 |
| 账单名称 | Body/Headline、Semibold | 最多两行，详情页不截断 |
| 辅助说明 | Subheadline / 14–15pt | 使用 `inkMuted` |
| 状态/标签 | Caption / 12–13pt、Semibold | 状态必须同时有文字 |

默认内容水平内边距 20pt；列表行最小高度 78pt；控件和图标可点击区域不小于 44×44pt；主要按钮高度 52pt；普通输入控件高度至少 52pt。页面底部滚动内容须避开 Tab Bar、键盘和 sheet 安全区。

形状沿用现有方向：主面板 28pt、普通组 20–24pt、按钮 16pt、输入控件 14pt、状态胶囊 999pt。内容列表优先使用留白与细分隔线，不套多层卡片。

## 5. 页面规范

### 5.1 首页

顶部显示问候、当前月份/星期和通知入口。首屏优先级：

1. 下一笔支付主面板：金额、账单名称、到期日期、相对时间、状态。
2. 直接操作：待支付显示“标记已还”；逾期显示“需要处理”并使用 danger 语义；右侧进入详情。
3. 本月进度：已完成、待支付、未知金额数量和轻量进度条；金额未知须明确标注。
4. “接下来”列表：按到期时间排列，展示未来最多四项。

主面板是内容层的高对比清晰面板（可用 `ink`/`danger` 实色），不是 Liquid Glass。空状态文案为“先记下第一笔固定支付”，提供单一“新增账单”入口。下拉刷新只反馈数据状态，不改变布局。

### 5.2 日历

顶部显示“账单日历”和已加载的有限窗口说明。月份日历为清晰的 `surface` 面板：今天用边框，选中日期用 `accent` 实色，非当月日期降低明度；日期下最多显示三个状态点，并用 VoiceOver 暴露完整笔数与状态。

左右切月按钮只允许在已物化窗口内操作；越界不可操作并提供可访问提示。选中日期下方显示日期、到期数量和账单列表；无记录显示“这一天没有付款安排，可以安心一些。” 新增操作使用导航/toolbar 的主要操作层，可在 iOS 26 采用玻璃按钮。

### 5.3 账单列表

导航标题为“账单计划”，副标题说明固定支付数量和有限提醒窗口。筛选项为横向可滚动的 segmented/chip：全部、待处理、已完成、已暂停、已归档。选中态同时由文字、填充和 VoiceOver 状态表达。

列表行显示类别图标、账单名称、到期日期/相对时间、金额和状态。金额未知显示“金额待确认”，不显示零元。行点击进入详情；新增使用 toolbar 或底部主要操作。加载、空列表、筛选为空和数据错误分别设计，不用同一条空文案覆盖。

### 5.4 账单详情

NavigationStack 标题“账单详情”，toolbar 放编辑与更多操作。首个清晰内容面板展示类别、名称、机构、计划/账期状态、金额、日期和当前账期操作。

账期操作：待支付提供“标记已还”和“跳过本期”；已完成/已跳过提供“恢复为待支付”。操作后使用短暂 confirmation banner 或 toast，并保留当前滚动位置。跳过不删除历史事实。

下方依次为“账期记录”“付款安排”“提醒”“备注”。账期记录用平面列表或浅色组，显示期数、日期、金额、状态和完成日期。付款安排显示首期日期、重复周期、支付方式、账户尾号和生成范围。提醒明确展示提前天数、提醒时间和“数据已保存在本机”。

暂停/恢复是可逆操作；如果保留归档能力，归档须使用确认 sheet/alert，明确“默认列表隐藏、历史保留、之后可以恢复”。不要把归档和物理删除放在同一入口。

### 5.5 新增/编辑

使用全屏 sheet，顶部关闭、标题和保存 toolbar；键盘出现时保存操作仍可达。表单分组：账单类型、基本信息、周期与日期、提醒设置、备注。

- 类型：信用卡、房贷、贷款、保险、订阅、其他；使用带图标的选择控件。
- 基本信息：账单名称必填；机构、尾号选填；尾号最多四位。
- 金额：每期金额可未知；未知金额必须是显式开关，并说明不会按 0 元统计。
- 周期：一次性、每月等已有业务周期；非一次性可填写分期总数，空值表示持续生成。
- 日期：首期到期日使用系统 DatePicker；提醒时间使用系统 TimePicker。
- 自动扣款：说明仍需检查余额和扣款结果，不宣称应用可支付。
- 提醒：提前 7/3/1 天或当天，可多选但至少一项；保存前校验。
- 备注：可记录扣款账户或注意事项，不用于新增分类能力。

校验错误就地出现在字段下方；保存失败保留用户输入；保存中禁用重复提交并显示进度。编辑计划时明确提示：已生成账期的历史快照不会被覆盖。

### 5.6 统计

标题为“账单统计”。顶部突出当前月份的已确认金额，并标注“有效待还与已还账期”；未知金额单独计数。完成进度同时呈现已完成、待支付、未知金额，不只展示百分比。

类别分布使用水平条形图和类别名称/金额；未来六个月使用简洁柱状图或 Swift Charts。图表旁提供文字摘要，未知金额以 `?` 或说明标记，不伪造数值。统计页面不引入预算、消费流水、投资或财务建议。

### 5.7 我的

顶部为“本地体验模式”，说明计划数量和数据只保存在本机；不出现登录/注册入口。分组包括：

- 提醒：账单提醒开关、系统通知状态、允许通知或前往系统设置。
- 数据：统计与趋势、云端同步（仅显示未启用状态，不提供伪同步）、导出本地备份、恢复本地备份。
- 关于：版本与本地优先说明。

恢复备份必须二次确认，展示计划/账期/提醒规则数量，并明确“完整替换当前本机数据、无法撤销、备份为明文”。危险说明使用 warning/danger 语义但不滥用红色。

## 6. 组件与状态

### 组件清单

- `DueDayTabBar`：四个主 Tab；iOS 26 使用系统玻璃，旧系统使用 surface 背景。
- `DueDayNavigationBar` / `GlassToolbarAction`：标题、返回、编辑、更多、新增。
- `NextPaymentPanel`：下一笔内容层主面板。
- `BillRow`：类别、名称、日期、金额、状态。
- `StatusBadge`：待支付、已完成、已逾期、已跳过、已暂停、已归档。
- `ProgressSummary`、`CategoryBarChart`、`ForecastChart`：统计组件均有文字替代。
- `FormSection`、`DatePickerRow`、`ReminderSelector`：表单分组与系统控件封装。
- `ConfirmationSheet`、`InlineMessage`、`EmptyState`、`LoadingSkeleton`：反馈状态。

### 业务状态呈现

| 状态 | 文案 | 视觉 | 可用操作 |
| --- | --- | --- | --- |
| pending | 待支付 | accent | 标记已还、跳过、详情 |
| overdue | 已逾期/需要处理 | danger + 文本 | 标记已还、跳过、详情 |
| paid | 已完成 | muted、勾选/文字 | 恢复为待支付 |
| skipped | 已跳过 | muted、跳过图标/文字 | 恢复为待支付 |
| paused | 已暂停 | warning + 文本 | 恢复计划 |
| unknown amount | 金额待确认 | warning 辅助提示 | 编辑补充金额 |

状态不得只依赖颜色；状态标签、图标、VoiceOver 描述至少保留两种线索。逾期由“待支付 + 日期”动态推导，不作为会被编辑覆盖的永久事实。

## 7. 交互与动画

- 高频导航使用系统 push/tab 过渡，无额外延迟。
- 按压反馈约 120ms，缩放不超过 0.98；不要在玻璃按钮上叠加重阴影。
- 状态切换约 180ms ease-out，只改变透明度、颜色、勾选或轻微缩放；金额不做跳动动画。
- 日历选中日期和筛选列表使用淡入/内容替换，避免整页闪烁。
- Sheet 遵循系统拖拽、交互式下拉和键盘避让；危险确认不可用滑动误触直接完成。
- 成功反馈优先短 confirmation banner；错误反馈包含原因和可执行的“重试”。
- 支持 `accessibilityReduceMotion`：关闭缩放、图表动画和复杂过渡，保留状态变化本身。

## 8. 深色模式

深色模式必须保持内容层清晰：背景使用深墨色，surface 与 canvas 保持至少一层可感知差异；文字和状态色按对比度重新选择。Liquid Glass 仅放在导航/操作层，系统玻璃在深色模式自行提供材质分离。

主金额、日期和状态不能因深色模式变成低对比灰色；图表每个类别仍需文字标签。逾期使用 danger 色和“已逾期”文字，已完成使用 muted 但不能低于可读对比度。测试纯黑背景、辅助功能增大对比度和降低透明度设置。

## 9. 动态字体与无障碍

- 所有文本使用语义字体样式或可缩放自定义样式，不固定 frame 高度，不用 `minimumScaleFactor` 掩盖不可读文本。
- Dynamic Type 至少验收默认、`accessibility1`、`accessibility3`；金额、按钮和状态标签不得截断。
- 账单行在大字级下由横排改为上下排；表单双列输入改为单列。
- 触控目标最小 44pt；图标按钮提供清晰 `accessibilityLabel` 和必要的 `accessibilityHint`。
- 日历日期读作“8月14日，今天，2笔账单，1笔逾期”，不能只读数字。
- 状态、图表和进度同时提供文字；不要用颜色作为唯一信息。
- VoiceOver 顺序遵循任务：下一笔标题 → 金额 → 日期/状态 → 主要操作 → 次要操作。
- 支持 Reduce Motion、Increase Contrast、Differentiate Without Color；系统放大文字时保持水平滚动筛选可操作。
- 中文文案避免只写“完成/处理”，使用“标记已还”“恢复为待支付”等明确动作。

## 10. iOS 26 与 iOS 17–25 差异

| 区域 | iOS 26 | iOS 17–25 |
| --- | --- | --- |
| Tab Bar | 系统 Liquid Glass，滚动时按系统规则增强材质 | 不透明 `surface`，细边框/阴影分隔 |
| Navigation/Toolbar | 系统玻璃容器，主要操作采用 tinted glass button | `canvas/surface` 背景，标准 bordered/filled button |
| Sheet | 系统玻璃承载层、drag indicator、系统 detent | 同样的 sheet/detent 和 drag indicator，使用不透明 surface |
| 主要操作 | 玻璃按钮可叠加轻量 tint | 实色 accent 按钮，确保高对比 |
| 内容卡片 | 仍保持清晰内容层，不使用玻璃 | 完全相同 |
| 动态与可访问性 | 遵循 iOS 26 系统材质与 Reduce Motion | 使用 SwiftUI 原生 fallback，行为不变 |

通过 `#available(iOS 26, *)` 隔离材质实现，不在业务 View 中散落版本判断；封装为原生组件，使旧系统只替换材质而不改变布局、文案、导航和状态逻辑。不得为了模拟 Liquid Glass 引入自定义模糊层覆盖内容。

## 11. 首轮实现优先级

### P0：可用闭环

1. SwiftUI App/Shell、NavigationStack、四 Tab、状态保持与安全区处理。
2. tokens、系统字体、Light/Dark、Dynamic Type、基础无障碍。
3. 首页下一笔、未来列表、标记已还与详情跳转。
4. 账单列表筛选、详情、暂停/恢复、跳过本期、归档确认（若当前业务保留归档）。
5. 新增/编辑完整表单、未知金额、日期/提醒、保存校验。
6. iOS 26/旧系统导航材质 fallback。

### P1：核心检查效率

1. 日历月份切换、日期选择、当天账单列表。
2. 统计完成进度、类别分布、六个月趋势和文字摘要。
3. 我的页面通知状态、系统设置入口、本地备份恢复确认。
4. loading、空状态、错误重试、成功反馈和 Reduce Motion。

### P2：打磨

1. 图表读屏摘要、横向筛选在大字级下的布局优化。
2. iPhone 小屏/横屏与 iPad 宽容器适配。
3. 玻璃材质在不同壁纸和深色模式下的对比度微调。

## 12. 首轮验收截图清单

每张截图应包含状态栏或安全区、完整页面标题和当前系统版本；同一测试数据用于 Light/Dark 对比。优先在 iPhone 17 Pro Simulator（iOS 26）和一台 iOS 17–25 模拟器各采集一份。

1. 首页：有待支付下一笔、逾期下一笔、金额未知、未来列表和本月进度。
2. 日历：今天、选中日期、逾期点、跨月日期、无账单日期。
3. 账单：全部、待处理、已完成、暂停、归档五种筛选；空筛选状态。
4. 详情：待支付操作、跳过本期、已完成恢复、账期记录、付款安排、提醒、备注。
5. 新增表单：分类、未知金额、周期、日期、提醒、自动扣款、校验错误和保存中。
6. 编辑表单：历史快照不覆盖的提示、金额补充和保存成功反馈。
7. 统计：本月完成进度、类别分布、未知金额说明、未来六个月图表。
8. 我的：通知未决定、已授权、已拒绝三种状态；备份恢复二次确认。
9. 深色模式：首页、列表、详情、表单、统计各至少一张，检查玻璃导航与内容层分离。
10. Dynamic Type：较大文字下的首页、账单行、表单和详情；不得截断主要金额/按钮。
11. VoiceOver/Reduce Motion：录制或截图辅助说明，确认状态、图表、日历和操作可理解。

## 13. 依据与未验证项

### 依据

- `PRODUCT.md`：产品目的、固定支付边界、核心流程、本地优先、未知金额、历史事实与高频/破坏性操作规则。
- `DESIGN.md`：温暖清单方向、颜色、形状、动效和无障碍基线。
- 现有 Flutter 页面与主题实现：下一笔、本月进度、日历、账单筛选、详情操作、表单、统计、通知和本地数据设置的既有信息架构。
- 现有领域模型：账单计划、账期快照、待支付/已完成/已跳过及计划状态边界。

### 未验证项

- 尚无原生 SwiftUI 实现，因此未验证真实 `#available(iOS 26, *)` Liquid Glass API 的最终编译写法。
- 未在 iOS 26 真机及 iOS 17–25 模拟器执行截图、滚动、键盘、深色模式或材质对比测试。
- 未验证 SwiftUI Charts 在极大 Dynamic Type、横屏和 VoiceOver 下的最终布局与读屏表现。
- 未验证本地通知、文件导入/导出在原生迁移后的系统权限与恢复错误路径；本规范只保留现有产品行为边界。
- 未验证实际中文字体在所有 iPhone 尺寸上的字宽；首轮实现需按验收截图清单补测。
